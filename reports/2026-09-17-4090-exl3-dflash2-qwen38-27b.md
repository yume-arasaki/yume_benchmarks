# RTX 4090 engine swap: EXL3 + DFlash2 on Qwen 3.8 27B

2026-09-17 · [@yume_arasaki](https://x.com/yume_arasaki)

Sequel to the [drag race](2026-09-15-4090-drag-race-qwen38-27b.md). Someone built a different engine for the same model and card class, so I swapped it in over an afternoon and ran my whole grid against it.

The build is [r0b0tlab/qwen38-exl3-dflash2](https://github.com/r0b0tlab/qwen38-exl3-dflash2): an ExLlamaV3 fork (branch `dflash2-pathway`, tip `30846b8`) with a native DFlash2 pathway, plus their published quants. Target [Qwen3.8-27B-EXL3-4.00bpw](https://huggingface.co/r0b0tlab/Qwen3.8-27B-EXL3-4.00bpw) (head 6 bpw, 15.4 GiB), drafter [Qwen3.8-27B-DFlash2-EXL3-4.00bpw](https://huggingface.co/r0b0tlab/Qwen3.8-27B-DFlash2-EXL3-4.00bpw) (1.2 GiB). Host route on the hamster account, no docker needed: uv-managed Python 3.13, torch 2.10.0+cu128 off plain PyPI (pypi.nvidia.com times out from my box), fork deps, ninja + nvcc on PATH for the JIT build. Their own container route hits the same no-sudo wall on their box, documented in their RESULTS.md.

## The headline

Their acceptance gate, rerun on my card: acceptance **5.50** (they publish 5.474, MTP head 4.101), which lands **181.5 tok/s** on their GSM8K greedy harness. Their 3090 reference is 152.4, no-drafter baseline 41.8.

My real-prompt cohort (same 8 prompts, 1024 out, two-point timing, two reps): **144.5 / 145.9 decode, 139.2 / 143.2 e2e, TTFT 117-284 ms**. Previous lane record on this card was 140.4 decode on the vLLM stack. Different serving stacks, printed never subtracted.

## Context

Full 262,144-token window on 24 GB: cq3 KV, 22.6 GB resident idle, 24.1 GB peak at depth. Their claim held up under testing.

## Landmines

Four, all reproducible:

1. **Their long-context corpus is Pride and Prejudice, which tokenizes to 174,870 tokens.** Anything the script reports as "200k+" is silently the same ~175k prompt. My apparent decode cliff at 200k was the model hitting EOS mid-book, not a speed wall; with EOS suppressed it decoded fine at depth.
2. **The needle script's 256-token answer reserve overflows the 262,144 cache at exactly full window.** Failure mode is evil: HTTP 200 with zero completion tokens in half a second, no error anywhere. Fit is prompt + reserve <= 262,144.
3. **The serving shim ignores the `tools` field.** Tool schemas never reach the model; it falls back to text protocol or refuses.
4. **My own harness artifact, caught the hard way.** A structured-count rep read 631.3 tok/s. The two-point method's 1-token probe absorbed cold prefill + JIT (976 ms) while the full pass ran warmed, so `(ct-1)/(t_full - t_probe)` divided by a falsely-small base. The tells: rep1 >> rep2 while e2e agrees across reps (decode cannot diverge when e2e doesn't), and the number sat 2.4x past the engine's physical ceiling (8 tokens x 33 steps/s on this stack). Warm-rerun with proper warmup: 277.0/276.9. Every decode number now gets a physics bound and a warmup protocol before it ships.

## Two engines, one card

vLLM keeps prose and agent turns (175.1 prose, streaming, real tools). EXL3 + DFlash2 takes structured work, the cohort record, half-energy agent turns (2.64 vs 5.09 J/tok on the same shape), and the full 262k window. The vLLM lane is the 64k fast boot; this stack holds the whole window in the same VRAM.

## What I didn't run

No quality battery on this stack yet (the vLLM lane passed GSM8K 95.5 on the same model; different quant though). No concurrency lanes, the shim is single-sequence FIFO. No wall power, GPU rail only, 350-366 W under load. No soak test, one evening.
