# Six tools, one shot, two models: 47/51 against 48/51

*BENCH-agent v1. The same DeepSeek-V4.1-Flash at 2.9 bits per weight on my desk and at full BF16 in the cloud. Six prompts, one generation each, no repair. The local side scored 47 of 51 checks. The BF16 side scored 48. The interesting part is that the small one told me about its own bugs before I found them.*

## WHY I BUILT THIS

I like the myllmbox suite. It put twelve one-shot pages in front of me and asked whether they were good. But a page can be beautiful and dead, and I wanted the other axis: can a model build something that *works*, and can it prove it?

The prompt asks for two things. A finished-looking tool, and a small API on `window` that a machine can call. The artifact also has to expose `window.__selftest()` and show the counts in its own header. I never trust that panel. My harness calls the API with fixtures the model never saw, twice, through headless Chrome. If the model hardcodes my examples, it fails anyway. If it lies in its self-test, the external call catches it.

Six artifacts: a VM, a scheduler, a queue simulator, an expression parser, an A* pathfinder, and a 20,000-instance three.js view. Each one is a self-contained HTML file with no network and a seeded PRNG.

## THE METHOD

The local side runs on two DGX Sparks over RDMA: Mia's TensorFold Zig kit, EXL3 2.9 bpw, a 1,048,576-token window, four seats, about eighty tokens a second. Each of the six was generated by the Sirius harness on the lane at port 8007, one attempt, no repair, then copied out as-is.

The cloud side is the same model at full BF16, and I have to be plain about how it got here: the assistant wrote those six files by hand, in the same session, from the same prompts. There is no endpoint on this machine, no key, no serving stack. That is a served quant against an authored set, and every surface says so. I do not quote a cloud throughput figure; inventing one would be the only dishonest number on the card.

The fixtures are run twice per artifact to catch nondeterminism. All twelve artifacts agreed with themselves across both runs.

Before the six tools, the same lane had already run myllmbox's suite: twelve one-shot pages and sixty-three throughput cells. Its gauntlet averaged 80.6 tok/s, throughput plateaued at 156.6 on mixed content, and the site scored it 2.16 of 3 for gauntlet speed and 16.36 of 22 for throughput against its pair. That suite judges a still page. This one asks whether the page works.

The BF16 side has a miss of its own: my ORBIT page drew twenty thousand bars in black on black, and its self-test still said seven of seven — I tested the scene graph, never the pixels. A task that paints nothing scores zero, so my side is 48 and the gap is one check.

The small one is not embarrassing itself. It wrote an expression parser that passed eighteen values, two variable cases, five error cases with offsets, and an AST check — twenty-two for twenty-two. It wrote an A* that returns optimal costs on three hand-checked maps, refuses a walled-off goal, and never cuts a corner. It put twenty thousand instanced bars in a scene with zero NaNs.

## WHERE IT LOST, AND WHAT IT SAID

It lost four checks; three are one bug.

On the VM, every program with a loop hits the 10,000-step cap: factorial, fibonacci, and a simple sum all return `halted-cap` with an empty output. The jump is wrong. The scheduler returns a critical path of just `[D]` instead of the full chain — the makespan and the dependencies are right, so it is the path walk, not the graph.

Here is the part I keep coming back to. Its own panel reported `SELFTEST 6/12` on the VM and `11/12` on the scheduler, and listed the same failures my harness found, by name. It did not claim a pass. A model that cannot fix a bug in one shot is expected. A model that ships a red test and tells you why is doing something I want from software.

## WHAT I THINK THIS MEASURES

Contract-following, mostly. The six prompts agree on a shape — one file, a fixed API signature, plain JSON, a self-test, a seed — and the work is to hold all of that at once while also being correct. At 2.9 bits the model held the shape everywhere and the correctness almost everywhere. The gap is one bug class: loops and path reconstruction, the places where state has to survive more than one step.

I would not read this as "BF16 is better." One sample per task, one fixture set, a hand-authored other side. I read it as: the quantized model can build the thing, and its self-verification is honest.

Two more three.js prompts came after the six: a cutaway tower and a voxel siege. The tower broke the local model — a TypeError every frame, a blank canvas — while the siege is the best thing it built all night. I did not score those with fixtures; the page shows them side by side.
